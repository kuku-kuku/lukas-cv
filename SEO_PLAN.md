# SEO implementation plan (2026-11-19)

Source brief: `BENETA-CLAUDE-CODE-SEO-PROMPT.md` + `beneta-seo-research.md`.

## What I found

- **Framework:** React Router 7 (framework mode), Vite, Tailwind. `ssr: false` +
  `prerender` list in `react-router.config.js`: every content route is written
  to static HTML at build time. Hosted on Vercel (`vercel.json`, output
  `build/client`, `trailingSlash: false`, rewrite only for `/demo/*`).
- **SEO mechanism:** `src/design/seo.js` `buildMeta()` builds title, description,
  canonical, OG/Twitter, `og:locale(:alternate)` and hreflang per route; each
  route module exports `meta()`. `<html lang>` is set from the path in
  `src/root.jsx` (server-rendered). Business + WebSite JSON-LD is emitted in
  `root.jsx`; Service + BreadcrumbList on service pages.
- **Content:** service pages are data in `src/design/pages.js` rendered by
  `src/routes/service.jsx`; home copy is i18n keys in `src/i18n.js`; prices
  live only in `src/design/content.js` (`PACKAGES`, `CARE`, `HOURLY`).
- **Sitemap:** generated by `scripts/build-sitemap.mjs` from the prerender list.
  **404:** prerendered `/404` → `404.html`, served with status 404 by Vercel.
- **House rules in code:** plain hyphens only (`scripts/check-dashes.mjs` fails
  the build on en/em dashes), no invented facts.

## Research "gaps" that turned out to be already fixed (verified in built HTML)

| Research claim | Reality |
|---|---|
| No `<html lang>` | `lang="lt"` / `lang="en"` in the prerendered HTML |
| No hreflang `/` ↔ `/en` | lt / en / x-default present in `<head>` of both |
| No JSON-LD | ProfessionalService + WebSite on every page; Service + BreadcrumbList on service pages |
| Soft 404 | Real 404 already in place |

## Real gaps → changes

1. **Sitemap** (`scripts/build-sitemap.mjs`): xhtml alternates on `/` and `/en`;
   lastmod from the git date of each page's source files (today if they have
   uncommitted changes, previous sitemap value if git is unavailable, e.g. on
   Vercel); drop `priority`. Adds the new page automatically via `prerender`.
2. **Non-www links:** footer domain link and the beneta project `liveUrl` →
   `https://www.beneta.lt`.
3. **Language switcher:** `<button onClick=navigate>` → `<Link to hrefLang lang>`,
   same classes (crawlable, no visual change).
4. **New page `/svetainiu-kurimo-kaina`:** data in `pages.js` (`PRICE_PAGE`),
   route `src/routes/price.jsx`, rendered by the same layout as the service
   pages. The shared layout moves from `routes/service.jsx` into
   `src/components/ServiceLayout.jsx` so both routes use one component. The
   section renderer gains: H3 sub-blocks, a simple table, a package price grid,
   and inline `[text](/path)` links in copy.
5. **`/#pricing` → `/svetainiu-kurimo-kaina`** on every service page; footer
   `Kainos` link; homepage pricing link under the cards; homepage FAQ price
   answer link.
6. **Page copy** per §5 (titles, descriptions, H1s, H2 renames, new sections,
   new FAQs) in `pages.js`, home meta in `routes/home.jsx`.
7. **JSON-LD:** move all schema into `src/design/schema.js`: separate `Person`
   node with `@id`, OfferCatalog with `@id …/svetainiu-kurimo-kaina#catalog`,
   FAQPage generated from the same arrays the visible FAQs render
   (home, /en, service pages, price page), WebPage / CollectionPage nodes.
   **Note:** this reverses a deliberate 2026-11 removal of FAQPage
   (comment in `seo.js`); the brief asks for it explicitly, and the markup is
   valid and harmless.

## Deliberately not changed

- Homepage "Kuo galiu padėti" capability rows are interactive buttons (hover /
  accordion matrix). Turning them into links would change the interaction
  design. Each capability's detail already carries a real link to its service
  page, and the footer links every service page from `/`. Left as is.
- Main navigation, layout, animations: untouched.
- No new dependencies. No Lighthouse package is installed and the brief forbids
  adding dependencies, so Lighthouse runs are listed as a manual step.
